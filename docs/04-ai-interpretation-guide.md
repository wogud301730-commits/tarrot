# 04. AI(OpenAI) 해석 가이드 — 신뢰성 있는 타로 해석 만들기

> 상위 문서: [`../PRD.md`](../PRD.md) §9 (핵심 차별점), [`02-database-schema.md`](./02-database-schema.md)
>
> 이 문서는 이 프로젝트에서 가장 중요한 문서입니다. "AI가 그럴듯하게 지어내는 것"을 막고, **검증 가능한 근거에 기반한 해석**을 만드는 방법을 정의합니다.

## 구현 범위 (Scope)

- OpenAI API 호출 시 프롬프트 구조, 참고자료 주입(그라운딩) 방식, 응답 형식, 안전 가이드라인을 정의한다.
- "신뢰할 수 있는 타로 지식"을 이 프로젝트에서 어떻게 실제로 확보하고 검증하는지(운영적 정의)를 정의한다.

## 제약 조건 (Constraints)

- 카드 의미는 절대 모델이 그 자리에서 자유 창작하게 두지 않는다. 항상 `cards` 테이블의 시드 데이터를 프롬프트에 먼저 주입한다.
- 응답에 죽음, 질병, 사고, 이혼 등 **단정적이고 부정적인 예언성 표현을 확정형으로 쓰지 않는다** — 항상 "성찰/가능성"의 언어로 순화한다.
- 모델 호출 파라미터(모델명, temperature 등)는 코드에 하드코딩하지 않고 환경변수/설정 상수로 분리한다.

---

## 1. "신뢰성 있는 타로 지식"의 운영적 정의

실시간으로 외부 타로 사이트의 "리뷰 순위"를 크롤링해 모델을 고르는 것은 이 프로젝트 범위(정적 웹앱 + 서버리스 함수)에서 안정적으로 유지보수할 수 없습니다. 대신 신뢰성을 아래처럼 **재현 가능한 절차**로 정의합니다.

1. **표준 체계 채택**: 78장 카드의 정/역방향 의미는 가장 널리 통용되는 라이더-웨이트 계열 표준 해설을 기반으로 작성한다.
2. **교차 검증**: 각 카드 의미를 등록하기 전, 서로 독립적인 2개 이상의 공신력 있는 공개 타로 레퍼런스 자료를 대조하여 공통적으로 등장하는 핵심 의미만 채택한다 (`data/seed-cards.json` 작성 시 적용, `02-database-schema.md` §4).
3. **모델은 해석자이지 지식 출처가 아니다**: OpenAI는 위 1~2에서 확정된 의미를 "문장으로 풀어 설명하고 사용자의 질문에 맞춰 톤을 조정하는 역할"만 수행한다. 새로운 상징 의미를 만들어내지 않는다.
4. **투명성**: 결과 화면에는 항상 "표준 타로 의미를 기반으로 AI가 해설한 내용이며, 오락 목적입니다"라는 문구를 노출한다 (`../PRD.md` NFR-6).

## 2. 프롬프트 구조 (그라운딩)

서버(`lib/openaiClient.js`)는 아래와 같은 구조로 메시지를 구성한다.

**System 메시지** (고정, 코드에 상수로 관리):
```
당신은 타로 해설가입니다. 아래 [참고자료]에 주어진 카드 의미만을 근거로 해설하세요.
[참고자료]에 없는 새로운 상징이나 의미를 임의로 만들어내지 마세요.
확정적인 예언(예: "반드시 ~할 것이다", 죽음/질병/사고/이혼 등 단정적 부정 표현)은 쓰지 말고,
성찰과 가능성을 제안하는 어조로 작성하세요.
의학적·법률적·재정적 조언으로 해석될 수 있는 단정적 문장은 피하세요.
```

**User 메시지** (요청마다 동적 생성):
```
[스프레드]: {spread.name_ko} ({position_labels 나열})
[사용자 질문]: {question 또는 "질문 없음"}

[참고자료]
1번 위치({position_label}): {card.name_ko} ({orientation})
  키워드: {keywords}
  표준 의미: {upright_meaning 또는 reversed_meaning}
2번 위치: ...

위 참고자료를 바탕으로 다음 JSON 형식으로만 답하세요:
{
  "summary": "한 문장 종합 메시지",
  "per_card": [ { "position_index": 0, "text": "해당 카드 해설 2~4문장" } ],
  "overall_message": "전체를 종합한 3~5문장 해설"
}
```

- **응답 형식**: OpenAI Structured Output(JSON 스키마 강제) 기능 또는 `response_format: { type: "json_object" }`를 사용해 파싱 실패 가능성을 줄인다.
- **모델 선택 기본값**: 비용 효율적인 소형 모델(예: `gpt-4o-mini` 계열)을 기본값으로 하고 `OPENAI_MODEL` 환경변수로 교체 가능하게 한다.
- **temperature**: 0.6 이하 권장 (창작성보다 일관성 우선).
- **타임아웃**: 20초. 초과 시 `03-backend-api-spec.md`의 502 처리 절차를 따른다.

## 3. 안전 가이드라인 (Safety)

- 다음 주제는 시스템 프롬프트에서 명시적으로 회피하도록 지시한다: 사망/질병의 확정적 예언, 특정 인물에 대한 폭력적 서술, 확정적 재정 손실/이익 예언, 의료·법률 자문으로 오인될 수 있는 문장.
- 사용자가 질문란에 자해/자살 등 위기 신호로 읽히는 내용을 입력한 경우, 타로 해석을 그대로 진행하지 않고 정형화된 안내 문구(전문기관 상담 권유)를 대신 반환한다. (간단한 키워드 매칭으로 1차 필터링, 완벽한 탐지를 보장하지 않음을 문서에 명시)
- 모든 응답 하단에 오락 목적 디스클레이머를 고정 삽입한다 (`../PRD.md` NFR-6).

## 완료 기준 (Definition of Done)

- [ ] `lib/openaiClient.js`가 위 System/User 메시지 구조를 그대로 구현한다.
- [ ] 카드 의미가 항상 DB 조회 결과에서 오고, 프롬프트에 하드코딩된 카드 설명이 없다.
- [ ] JSON 파싱 실패 시 재시도(최대 1회) 후에도 실패하면 `03`의 502 처리로 넘어간다.
- [ ] 위기 신호 키워드 1차 필터링 로직이 존재한다.

## 검증 기준 (Verification)

- 동일 카드 조합으로 3회 반복 호출했을 때, 키워드/표준 의미와 모순되는 내용이 없는지 사람이 직접 검토한다 (최소 5개 서로 다른 카드 조합, 총 5건 이상 샘플 점검).
- 응답 텍스트에 "반드시", "확실히 죽는다/이혼한다" 등 금지된 단정적 표현이 없는지 확인한다.
- 결과 화면에 디스클레이머 문구가 매번 표시되는지 확인한다.
- 위기 신호 키워드(예: "자살", "죽고싶다")를 질문란에 입력했을 때 일반 타로 해석 대신 안내 문구가 반환되는지 확인한다.
